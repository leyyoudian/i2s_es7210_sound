# 声源定位稳健性与 bird-sound v2 模型集成设计

日期：2026-07-30

## 目标

在不改变现有 ESP32-S3、ES7210、四麦克风阵列和 16 kHz 采样架构的前提下：

1. 将推理模型切换为 `D:\Downlowads\bird-sound-cpp-mcu-v2`。
2. 降低声源方向跳到对角或错误象限的概率。
3. 避免静音、启动瞬态和低质量相关峰参与定位或触发鸟声识别。
4. 输出足够的诊断数据，支持上板验证 TDM 通道顺序和麦克风一致性。

## 已确认硬件约束

- 采样率：16 kHz。
- 麦克风阵列半径：约 25 mm；对径麦克风间距约 50 mm。
- 方位：MIC3=0°、MIC4=90°、MIC2=180°、MIC1=270°。
- 当前假设 TDM 槽位顺序为 MIC1、MIC2、MIC3、MIC4；该假设必须通过四路能量诊断实测确认。
- 50 mm 基线在 343 m/s 声速和 16 kHz 采样率下的最大物理时延约为 2.33 samples。

## 模型集成

把下载目录中的完整 `bird-sound-cpp-mcu-v2` 部署包复制到项目内一个明确的模型目录，并让 `components/edge_impulse/CMakeLists.txt` 只引用该目录。构建不依赖下载目录的绝对路径。

目标模型属性：

- 项目名：`bird-sound`
- 部署版本：2
- 输入：15488 samples @ 16 kHz，约 0.968 秒
- 标签：`bird`、`noise`

推理包装层按标签名称读取两个输出。启动时校验模型频率、标签存在性和输入长度；不再把所有非 `noise` 标签合并成鸟类，以免未来标签变化被静默误判。

## 定位处理链

每次收到四通道 PCM 帧后按以下顺序处理：

1. 计算四通道 RMS、峰值和削波状态。
2. 使用跨帧持久化的高通/低通滤波状态产生 GCC 输入。
3. 对四个麦克风组成的全部六个麦克风对计算 GCC-PHAT 互相关。
4. 根据四个麦克风的实际坐标，对 0°～359°候选方向按固定角分辨率执行 SRP-PHAT 网格搜索；每个方向累加六对麦克风在理论时延处的相关得分。
5. 对最佳方向附近的角度得分做插值，并以最佳峰、排除邻域后的第二峰及二者差值构成定位质量指标。
6. 若最佳得分、峰值优势、六对贡献一致性或音频能量不足，则本帧定位无效。
7. 使用短窗口圆周向量聚合剔除孤立跳点，再进行圆周平滑。只有有效帧更新跟踪器；无效帧保持最后一个可靠角度。
8. LED 仅在有效声源状态下显示对应方向。

质量阈值集中定义并在日志中可见。初始值采用保守默认值，上板采集数据后再校准；不能把未验证阈值视为最终参数。

## 识别处理链

- 新模型窗口长度直接使用 `EI_CLASSIFIER_RAW_SAMPLE_COUNT`，禁止另写固定长度。
- 每个推理窗口开始时选择 RMS 最大且未削波的通道；窗口内保持通道一致，避免拼接不同麦克风造成特征突变。
- 若整窗有效 RMS 低于静音门限，则不调用模型，直接向状态机提交噪声/无活动结果。
- 启动后的首个不完整窗口丢弃，避免上电和滤波器稳定过程进入模型。
- 鸟声状态使用 `bird` 概率、`noise` 概率和滞回阈值；初始阈值按二分类重新设置，并通过日志保留原始概率和门控原因。
- 本次不宣称代码阈值能弥补训练集与新麦克风、结构腔体和实际环境之间的域差异。后续应录制真实硬件 PCM，建立误报/漏报样本集再决定是否重训。

## 接口与代码边界

- `gcc_phat`：负责四麦六对 GCC-PHAT、SRP 角度搜索和相关质量，不负责 UI 或鸟声判断。
- 新增纯 C 定位跟踪模块：负责置信度门控、圆周聚合和有效状态，便于主机单元测试。
- 音频任务：负责四路帧统计、滤波状态、平滑状态和推理窗口组织。
- `ei_inference`：只负责模型输入转换、标签解析和原始推理结果。
- Web/LED 层继续消费最终角度、有效状态和鸟声状态，不感知 GCC 内部细节。

## 日志与诊断

以限频方式输出：

- `rms=[mic1,mic2,mic3,mic4]`
- 每通道峰值和削波标志
- SRP 最佳角、最佳得分、第二峰和峰值优势
- 六对相关贡献一致性、定位有效性及拒绝原因
- EI 使用通道、整窗 RMS、是否被静音门控
- `bird`、`noise` 原始概率和最终状态

诊断输出不能每帧刷屏；正常摘要约每秒一次，推理完成时额外输出一条。

## 测试与验收

主机单元测试覆盖：

- 六对理论时延均不超过各自基线的物理上限。
- SRP 角度插值在圆周边界和退化曲率下安全。
- 圆周角跨 0° 平滑正确。
- 低峰值优势和六对贡献不一致的结果均被拒绝。
- 无效帧不改变最后可靠角度。
- 新模型标签解析只接受明确的 `bird` 和 `noise`。

构建验收：ESP-IDF 全量构建成功，固件尺寸不超过当前 app 分区。

上板验收按顺序进行：

1. 依次近距离轻触或播放声音到四个麦克风，确认日志通道与物理 MIC1..MIC4 一致。
2. 在 0°、90°、180°、270° 固定声源，确认有效方向落在对应象限且不频繁跳到对角。
3. 在安静环境运行，确认方向无效且不会因启动瞬态持续触发鸟声。
4. 播放鸟声与非鸟声样本，记录概率、误报和漏报；识别效果以实测数据评价，而不是只看训练报告。

## 不在本次范围

- 将定位采样率提升到 32/48 kHz 并为模型降采样。
- 直接移植完整 ODAS 定位、跟踪和分离系统。
- 修改 PCB、麦克风间距或声学结构。
- 未经真实硬件数据验证就重新训练模型。

## 风险

- 16 kHz 下最大时延只有约 2.33 samples，亚采样插值只能改善估计，无法消除阵列孔径和房间反射造成的物理限制。
- 若实际 ES7210 TDM 槽位顺序与假设不同，算法映射仍会错误；诊断验证是上板验收的前置步骤。
- 新 v2 模型训练质量可能仍不足；模型替换只能保证集成正确，不能保证现实数据上的准确率。
- 新模型 SDK 与现有 ESP-IDF 编译选项可能存在兼容差异，需以全量构建结果确认。

## 算法参考决策

Espressif ESP-SR 已提供面向 ESP32-S3 的双麦 SRP-PHAT API，但接口只返回 0°～180°角度且不提供质量指标。直接运行两个双麦实例仍不能充分利用当前四麦阵列。ODAS 提供完整的多麦 SRP 定位与跟踪实现，但整体移植范围和资源开销超出本次需求。因此采用紧凑的四麦六对 SRP-PHAT：沿用项目现有 FFT 基础，只实现当前阵列需要的角度网格、得分和置信度跟踪。
