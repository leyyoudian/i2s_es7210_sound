# 声源定位调试记录 · 2026-11-18

本次实际修改的工程是 `i2s_es7210_sound (4)/i2s_es7210_sound`，不是同级 `i2s_es7210_sound-6`。前者有 2026-09/10 的模块化代码，串口日志与板上原固件对应。目录名中的数字不能作为版本先后依据。

本文保留各轮真实短录音与连续音乐测试记录；**当前交付镜像以文末第四轮为准**。

## 测试条件与结论边界

- ESP32-S3 + ES7210，COM25；48 kHz、四通道同步采集、1024 点分析帧。
- 用户提供初始距离约 1.7 m，初始方位约 225°～270°；随后在原地将板子旋转约 90°，喇叭不动。没有获得精确角度、旋转方向和扬声器布置的测量结果。
- 第三轮用户明确确认：阵列半径 40 mm，相对两颗麦克风中心相距 80 mm。代码几何与这个确认相符，未修改尺寸或固定角度偏置。
- 网络下载真实 WAV：ESC-50 的狗叫、鸟叫、拍手、木门敲击、咳嗽、钟表各两段；Free Spoken Digit Dataset 的人声三段，共 15 段。
- 使用同一电脑输出；峰值统一到 0.30，再以 `--gain 2` 播放，即 WAV 峰值 0.60；没有调整 Windows 主音量。它不是声压级标定。另测试了较低电平及左右单声道。
- 本记录中的“有响应”仅表示播放窗口内至少有一帧有效定位和显示门控输出。**不代表每一次声事件都识别成功，也不代表角度准确率 100%。** LED 状态是固件输出日志，未用摄像头确认实物亮灯。

## 已修复的具体问题

1. **LED 绕过回差**：门控保留旧灯位，却输出变化中的显示角度；驱动再次按角度选最近灯，从而绕过门控。现在物理灯使用门控确认的 `held_pixel`，网页保留连续角度。
2. **切灯主动制造闪烁**：原驱动先 `led_strip_clear`，再刷新，再点灯再刷新；RMT 后端的 clear 本身就发帧。现在先在缓冲区清零/点灯，只发送一次；去掉扫过中间方位的动画。
3. **瞬态条件与帧长不匹配**：1024 点帧中按 384 点块计算 RMS，尾块 256 点；峰值块/整帧 RMS 的理论上限为 2，无法达到强响指要求的 2.25。改为 96 点（2 ms）窗口。
4. **瞬态被二次门控丢弃**：有效瞬态仍等待音量 EMA 或显示候选的第二帧，造成听到声音而不亮灯。现在可信瞬态直接激活并保持短时间，通过跟踪器后可立即更新灯位。
5. **置信度被人为抬高**：移除瞬态置信度的固定上调；强声音同样需要真实置信度和镜像检查。
6. **相干性计算错误**：瞬时互谱的模不能表达跨帧相位一致性。现在先平均复数互谱，再计算相干性；增加按静音段学习的频谱噪声权重，避免安静频段在 PHAT 白化后等权投票。
7. **弱声首帧能量被低估**：频谱历史刚清空时直接以首帧功率和互谱初始化，避免零历史平均值压低首帧结果。
8. **持续声与瞬态互相污染**：持续声使用复数互谱积分；瞬态读取当前帧方向，不继承旧方向的角度轮廓。静音后清理历史；麦克风健康掩码变化也清理旧空间轮廓。
9. **低频信息缺失与宽峰误拒绝**：保留 300 Hz～6 kHz，兼顾人声/狗叫时差与鸟叫高频；置信度比较分离的局部峰，不把同一主瓣的肩部当成第二个声源。镜像分数高时仍需额外置信度。
10. **大跳变瞬态绕过跟踪器**：已跟踪声源期间的大跳变需重复确认；对侧跳变保持更严格确认。拒绝帧会中断对侧确认，不能把零散反射累积成一次切换。
11. **处理超时和丢帧**：使用工程已自带的 ESP-DSP S3 FFT 汇编核、缓存搜索延时、减少重复平方根计算。日志交给 Core 0 的独立队列任务。扩大 DMA 调度余量，并限制超时时的强制休眠频率；100 Hz RTOS 下每帧休眠一 tick 本身就会造成持续丢帧。发现溢出的帧不再用于换方向。
12. **测试统计串帧**：清主机串口缓冲不足以排空设备侧数据。测试脚本现在先持续读取至少 3 秒并等待 DOA 任务就绪，再开始播放；当前固件日志包含采样帧的 `frame_ms`，按采样时间对齐播放窗口。

## 仍未解决、不能掩盖的问题

- **精确角度尚未完成标定**。同一扬声器，不同素材的角度仍可能相差几十度；反射、扬声器频响/布置、麦克风通道差异及阵列尺寸都需要继续核对。保持原有 40 mm 半径模型，没有根据一个测试方向硬加角度偏置。
- 某些探索轮次确实出现过对侧离群结果；最终这组 15 段记录集中在旋转后的同侧，但这不能证明所有室内位置都已消除镜像。
- 较低播放电平仍会漏掉部分拍手、狗叫。不能用提高播放电平后的结果，宣称弱声召回已经全部解决。
- 强瞬态、帧边缘事件、近场削顶、多声源/同时播放的两个扬声器，尚未完成系统测试。当前无硬件声压、阵列尺寸及精确方位的独立测量。
- `DOA_PCM_DUMP` 诊断模式会暂停正常定位，只用于导出离散的同步四通道快照；交付固件为 **OFF**。

## 第二轮：完整连续音乐测试与修复

按用户要求，播放完整的 **Karissa Hobbs《Let's Go Fishin'》**，133 秒；不是合成测试音，也没有循环短片段。前后均使用同一 WAV、峰值 0.45、同一系统音量与当前板子位置。

音乐来源：<https://librosa.org/data/audio/Karissa_Hobbs_-_Lets_Go_Fishin.ogg>。原始文件 SHA256 与 librosa 官方音频登记表一致：`27b3667c396c1831511aa3c415fcf582b6e8be560cafb844c5b67b76b72c1cb3`。

署名及许可：Karissa Hobbs，CC BY 3.0；原发布页 <https://freemusicarchive.org/music/Karissa_Hobbs/Age_of_Flowers/09_Lets_Go_Fishin>。许可文本缓存于 `.fetch/music-long/attribution.txt`。

长播放暴露出三个问题：

1. **把每帧波峰当成新瞬态**：持续音乐也常有大于 1.6 的块/整帧 RMS 比值，导致额外 FFT 和瞬态方向更新频繁运行。改为检查相对前一帧的能量突升，并要求高于背景能量；普通节拍主要使用持续积分，真正新出现的短声仍可快速响应。
2. **持续跟踪状态进不去**：旧代码在瞬态 RMS 超过固定绝对阈值时不断清零持续声计数，音乐稍响就不能进入长积分。现在按声源连续有效时间计数，明确能量突升时临时加快积分，不抹掉整段持续声状态。
3. **有效声源被计入噪声底**：已激活且能量高于噪声底时，不继续抬高底噪；能量下降时仍允许回落。避免持续播放后门槛追着音乐上涨。

全部记录仍按板端采样时间对齐，排空串口后才播放。**“有输出”是至少有一帧通过跟踪/显示门控，不等于所有事件都检测到。** 精确物理方向未测量；离群记录只相对本次音乐/持续声集中方向约 300°计算，不能冒充角度真值。

### 本轮新增修复

1. **亚采样相关插值**：线性插值会在整数延时处产生折点，使角度极值偏向某些延时。改为四点三次插值，保持方向搜索曲面更平滑。
2. **覆盖真实小数延时的回归**：原测试声仅使用取整到采样点的通道延时，无法发现上述偏差。新增 72 个方向（每隔 5°）的解析小数延时测试。相同 C 算法离线对照中，平均误差约 0.379°→0.027°、最大约 1.205°→0.079°；**这是理想平面波算法测试，不是实机精度**。实际房间的反射、通道差异依然大于该误差。
3. **弱声初次锁定保护**：较低电平雨声曾产生一个约 63.7°的孤立有效结果，实际带内 RMS/背景 RMS 仅约 2.1。未建立方向时，瞬态单帧直接锁定需要至少 3 倍带内 RMS；已有方向时保留 1.8 倍。弱持续声仍可走普通连续帧确认，不通过强行抬置信度解决漏亮。
4. **减少新增插值开销**：有界麦克风延时用整数截断及负值修正替代每次 `floorf` 调用，整数延时直接取相关值；保留负延时及 0/360°完整回归，未增加大块查表内存。

## 第四轮：无丢帧四通道录音重放，改为基于空间证据接收弱声

本轮先保存实际四麦波形，再对同一份采集数据运行当前 C 算法，避免多次扬声器测试时环境噪声变化混淆结论。没有修改 40 mm 半径、80 mm 对径的几何，也没有按当前方向加固定偏置。

### 确认并修正的缺陷

1. **静音后重复清空空间历史**：旧判断为 `idle_frames >= 6`，在一直未达到门控时，每帧都重置相关谱，弱声无法积累。现在在第六帧只清一次，保留后续真实连续观测的相干性，麦克风失效/溢出时仍重置。
2. **弱声只按音量接收不足以区分噪声**：新增有约束的弱空间证据路径：带内 RMS 至少为背景的 1.3 倍、空间分数至少 0.010、置信至少 0.16、对侧比低于 0.60，而且方向峰须高于“所有麦克风对均零延时”的分数。原有强声路径保留，弱单帧仍不能直接绕过首次锁定保护。
3. **首次普通锁定需要连续证据**：正常定位首次获取从两次有效候选延长到五次候选。已通过独立质量检查的强瞬态仍可即时获取，不把所有短声都延迟五帧。跟踪器默认接口仍是两帧；正常应用显式配置五帧，以免影响调用者预期。
4. **零延时对照必须同时间尺度**：零延时分数与方向分数使用完全相同的 EMA 系数和初始化，避免拿历史方向峰比较当前背景值而在衰减段制造假证据。
