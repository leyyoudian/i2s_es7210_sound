# 开发与调试指南

## 构建环境

硬件为ESP32-S3 + ES7210 + 四麦十字阵列（半径40mm、对径80mm），16颗WS2812接GPIO1。本仓库实机验证的ESP-IDF版本为 **v5.4.2**；使用匹配版本的ESP-IDF终端，勿将其它工程的工具链/构建目录混用。

```sh
idf.py set-target esp32s3
idf.py -D DOA_PCM_STREAM=OFF -D DOA_PCM_DUMP=OFF build
idf.py -p PORT flash monitor
```

将PORT换成实际端口，如Windows的COM25或Linux的/dev/ttyACM0。串口115200，监视器按Ctrl+]退出。仓库包含板型使用的sdkconfig与2MB应用分区表；改变目标、分区、采样率或第三方依赖后需要重新验证。

## 网络与模式

不提供私有网络凭据时直接离线运行定位/灯效。需要网页面板时，将main/wifi/wifi_credentials.example.h复制为wifi_credentials.h，填写自己的2.4GHz网络；私有头文件被Git忽略，密码会嵌入本机编译的固件，因此不要公开该固件。

main/app_mode.h选择声源定位或音色识别，二选一；main/examples/examples.h选择独立外设例程或板级自检。所有例程开关保持注释时运行主程序。定位模式不执行分类推理，网页以主方向为准。

| main/doa/doa_display_gate.c | 网页/主灯原有显示门控 |
| main/doa/doa_led_scene.c | 双方向持续确认，不能把一帧回声直接变成第二灯 |

详细参数见[参数与动态灯效说明](参数与动态灯效说明.md)，不要用改动画的方式修改声学标定。

## 主机回归

现有C测试调用MSVC，网页测试调用Node.js，因此主机测试入口要求Windows、MSVC Build Tools、Node.js及Python 3.11/3.12。

```powershell
python -m pip install -r tools/requirements.txt
python -m pytest tests -q
```

测试包括：已知方向、小数采样延时、三麦降级、两独立源、镜像/跳变保护、弱空间证据、显示门控、原子灯带刷新、RGB强度、顺逆时针整圈及短尾灯约束。主机角度轨迹测试不等于实物声源已绕板验收。

## 日志字段

默认每16帧输出一次（约341ms），新声源或瞬态附近会额外记录。不要按日志条数直接计算有效时间，使用frame_ms对齐真实时间。

| 字段 | 含义 |
|---|---|
| DOA | 主跟踪器角度，板面坐标0～360° |
| raw | 本帧SRP角度已转板面坐标，但未经过主方向平滑；瞬态时可能使用当前帧峰 |
| rms=[...] | 四路宽带RMS，以int16满量程归一化 |
| tr、pr | 2ms短块峰值RMS，及其与整帧RMS之比 |
| srp、second、conf | 主峰、独立次峰、区分度；置信不是概率或声压 |
| mir | 主方向180°对侧分数/主峰分数 |
| br、fl | 约300Hz～6kHz滤波RMS与噪声底 |
| act、dsp | 声源激活，及主显示门控状态 |
| oc | 四通道削顶样本总数，不是只要非零就必定走近场通道 |
| us、ovf | 分析帧处理耗时微秒、I2S队列溢出累计数 |
| frame_ms | 对应音频帧的设备采集/处理时间戳 |
| fast、steady | 当前帧瞬态分析开关、连续有效帧计数 |
| led、lit | 原主灯位及保持状态，不是新动画RGB帧的相机观测 |
| peaks、sources | 空间显示峰数、提交给动画的方向数；尾灯不算第二音源 |
| status | 主跟踪器本帧是否更新，不代表整段音频或全部声事件通过 |

## 实机诊断顺序

1. 先确认rms/br是否随播放升高；若没有，检查音量、通道、电源和ES7210配置。
2. act=1但status=rejected时，看空间分数、置信、镜像、削顶和连续确认，不要仅为亮灯放低所有门槛。
3. 主方向稳定、灯光仍不好看时，只调led_effects_config.h；串口/网页角度与动画分开。
4. 观察ovf增量，溢出的拼接帧不会用于换方向。记录错误先修复，不能忽略丢帧后宣称精度。
5. 怀疑时序、反射或弱声时，用[工具说明](../tools/README.md)采集四通道PCM，确认CRC/序号/溢出均无错，再用同一份波形重放C代码。

## 已知限制

阵列半径、通道顺序、采样率和坐标映射必须与实际板子一致。近场、强反射、纯音、多个相近方向及极低信噪比均可能造成误差；亮度不等于距离，没有标定的声压和实际方位不能变成精度保证。一只音箱播放的白噪声仍有物理方向，真正分散噪声和音箱播放噪声不是同一个测试。

第三方SDK/模型和测试素材分别保留其许可。下载录音、私有网络配置、串口日志、固件备份、个人视频工程保存在忽略目录，不随源码提交。
